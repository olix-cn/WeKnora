# 会话知识来源索引与撤权边界

> 未部署。管理接口已挂载供受控测试；本设计不是全站数据撤回功能，范围见测试部署清单。

## 存储与一致性

PG141／SQLite57新增三张派生表：

- `session_knowledge_revisions`：消息变动版本及已解析版本。
- `session_knowledge_sources`：会话→知识库的单调来源集合，支持知识库反向索引。
- `session_knowledge_evidence`：来源字段被覆盖／删除前的临时证据，索引事务完成后压缩清除。

消息表 insert／update／delete 触发器负责失效标记，覆盖普通 repository、直接 SQL、fork和检查点修复。内容更新也更新版本，但只有来源字段、会话归属或软删除状态变化时保留旧证据，避免重复存储全部工具轨迹。

刷新事务锁定会话版本，读取当前消息及旧证据，合并来源、标记已解析版本并清理临时证据。并发消息写入的触发器必须更新相同版本行，不能把未解析的新来源错误标记为已解析。索引只新增来源，不因删引用／删消息自动移除，防止后续总结仍含原文却被降密。

临时证据可包含引用中的原文和工具结果，**仍是业务敏感数据**，不是可公开日志。不得记录到聊天、公开文档或诊断输出；备份、保留期及账号／会话删除清理需要在正式开放前纳入既有数据治理流程。

## 历史数据

- 迁移只将已有消息所属会话登记为待解析，不读取用户明文或调用模型。
- 首次使用时解析该会话已保存的引用、execution_context、mentions和结构化工具字段；旧字段被覆盖或软删除前会由触发器留证。
- 对迁移前消息标记 `legacy_unverified`，不靠空来源证明安全。成员若不可读本空间任一受限库，则保守拒绝这类旧会话（含标题／产物列表），管理员可读；fork继承标记。不自动清标记或尝试从改述猜测完整血缘。跨空间未知派生数据、记忆／外部导出仍需专门治理。
- 缺少迁移、冷回填超预算或解析失败不降级到同空间全可读。

## 列表与回填

列表先对每个受限知识库检查一次当前权限，再通过反向索引筛会话。已索引的2100会话合成验证不触发原2000会话冷扫描上限。

冷／变更会话仍有限额（一次2000会话、单会话消息和证据各10000条）；超过返回明确错误，不能只校验一部分就返回剩余列表。

维护原语 `BackfillSessionProvenance(ctx, db, after, limit)` 提供1–500条游标批次、可恢复进度、不输出正文；不自动启动、没有无鉴权HTTP入口。操作者必须使用隔离库测试，正式业务回填仍需维护授权。回填完成后从空游标再检查一次，处理回填期间发生的消息更新。

回退遇已保留来源或临时证据拒绝，不能静默删除单调依赖再从不完整的当前消息重建。清空派生数据不是普通回退步骤，必须单独评审。

## SSE连接

现有连接每批输出前重新检查会话来源和当前成员权限；续流初始回放也检查。拒绝或验证失败发送不含私有正文的终止错误，随后退出，不冲刷暂存文本或伪造complete。

这不是原子网络撤权：已传输内容不能收回，检查与发送之间仍有调度窗口；当前实现停止后续批次，不承诺撤权事务提交瞬间绝对零字节。当轮Agent／RAG目标在检索与模型输出前显式登记，失败即中止；来源和legacy标记由fork继承，不能仅复制当下可见引用。

## 验证

- SQLite实际迁移、触发器覆盖原始写入、未读即覆盖／软删除来源、证据压缩、回退保护、批量回填和反向索引过滤。
- PostgreSQL隔离库实际PG141脚本、并发消息更新与索引刷新不漏新来源、覆盖前来源留存、回退保护。
- 合成SSE两批输出中途撤权：首批可达，后批正文和complete不可达，返回knowledge_access_revoked。

证据采用原会话业务敏感数据与备份规则，成功刷新即压缩；软删不等于物理销毁。保留期／账号彻底删除、生产规模性能与跨派生系统血缘仍需正式上线前专门评审；受控测试仅合成资料，不宣称已完成全站撤回。

# CAD Assistant MCP：BOM 快照直出 Excel 优化提示词（第二版）

针对 schema/data 分页已有改善后的剩余问题。以下代码块可整体复制给 MCP 服务端开发 AI。
这是待实现要求，不代表相关功能已经完成或部署。

```text
请继续优化 CAD Assistant MCP 的 BOM→Excel 链路。本轮不是重做已完成的 schema/data 分页，而是打通“读取快照→定向取证→固定导出→可靠交付”，减少模型搬运数据和临时编程。

一、当前事实与优化目标

最近一次真实请求：
- 端到端约 152.76 秒。
- 主 Agent 13 次模型调用累计 108.96 秒。
- 等待 Excel 子任务约 40.66 秒；子任务自身约 70.45 秒，与父任务重叠，不能重复相加。
- 主链路 MCP 调用合计仅约 1.09 秒。
- 父模型手动整理全部数据并生成子任务消息耗时约 24.58 秒。
- 子模型生成约 7.32 KB Python 脚本耗时约 50.10 秒。
- Excel 脚本实际执行仅约 0.55 秒。

已经有效的能力：
- drawing_bom_extract 支持 schema/data/evidence/export 等模式。
- columns_mode=all 能保留全部物理列。
- result_id 与分页已可复用。
- BOM schema/data 单页约 1.72–6.83 KB，没有工具通道字符串截断。
- 结果明确区分 partial、未检测单元格和未解决的表头语义。

尚存问题：
1. Agent 仍先调用通用 drawing_read_files(summary)，约39 KB，普通 blocks/references 撑大结果并被截断。
2. Agent 将 BOM 行数据手抄到子任务消息，再由子模型写入 Python。
3. 已有原生 export，但其结果是工作站本地路径，不等于 WeKnora 可下载附件。
4. 父任务和子任务同时走两条导出路径；工作站导出因文件已存在而失败。
5. evidence 已存在，但歧义表头和未检测单元格未经过定向取证。
6. 最终是部分数据文件，不能称为完整原生 BOM。

本轮目标：
- 模型只传 result_id、范围和格式选项，不逐行抄数据。
- 服务端以固定代码生成 Excel，不要求模型每次生成脚本。
- 明确选择工作站导出或可下载文件交付，不重复生成。
- 保留全部完整性、权限和来源边界。

二、执行边界

1. 阅读仓库说明、AGENTS.md 和 Git 状态，不覆盖已有改动。
2. 先核对现有 schema/data/evidence/export 的实现和测试，给出最小改造方案。
3. 不修改 WeKnora 服务端、模型配置、客户端截断上限或工具权限。
4. 不安装依赖、不重启生产服务，不对真实用户图纸执行写入测试。
5. 不通过猜测表头、忽略问题、绕过确认或开启 CAD 来达到提速目标。
6. 不保证本轮一定能实现跨客户端文件下载。先验证真实协议支持，缺口必须明确说明。

三、让 BOM schema 成为直接入口

更新真实工具描述和 schema：
- 用户要求读取目录 BOM 时，可直接调用 drawing_bom_extract(mode="schema", directory=...)。
- drawing_read_files、drawing_list_files 不应是固定前置步骤；只有另有必要证据时才调用。
- schema 返回文件清单、表清单、列结构、读取范围和分页信息，足以支撑后续 data/export。
- mode=export 应直接消费已有 result_id，不要求客户端先把全部数据页读入模型上下文。
- 数据分页仍保留，用于人工检查、筛选和按需取证，不作为导出的强制前置步骤。

对于通用 drawing_read_files(summary)：
- 默认只返回数量、覆盖范围、关键属性和问题摘要。
- 普通块定义和引用明细按需分页/投影，不整批塞进 summary。
- 不硬截断 JSON，也不在没有完整性标记时静默省略数据。
- 保持现有参数的兼容性；必要时增加明确的摘要范围参数。

四、建立直接消费快照的固定 Excel 导出器

优先在现有 export 模式中实现，不另起一个重复的模型脚本流程。

输入以这些信息为主：
- result_id；
- 全列/指定列或稳定 column_id；
- 文件/表选择；
- 固定模板选项；
- 输出目标；
- 是否明确接受部分结果。

要求：
1. 从服务端保存的快照读取真实数据，不经过模型重新逐行构造。
2. 若快照尚未物化全部行，由服务端基于同一快照读取，不能混入修改后的文件版本。
3. 导出不要求客户端先遍历所有 schema/data 页。
4. 用固定导出函数生成工作簿、样式和完整性说明，不动态执行模型提供的 Python。
5. 复用现有已安装库，不新增依赖，除非先说明并获得批准。
6. 展示参数不改变源数据身份；业务筛选与导出配置需有可追溯指纹。
7. 如果 result_id 不包含导出所需数据，明确补齐快照设计，不能悄悄依赖模型手抄。

Excel 至少包含：
- BOM 明细；
- 文件/表读取状态；
- 数据来源、未解决问题及验证范围。

支持异构表头和多级表头：
- 使用按来源分表或明确的联合列映射。
- 保留原始表头路径、稳定列标识和来源。
- 不因同名将不同语义列强行合并。
- 不默认去重、跨层级汇总或做装配数量乘算。

五、完整结果与部分结果必须明确

当前样本有：
- 12行，两个表，每表8个物理列。
- 40个not_detected单元格。
- 4个重量列语义ambiguous。
- 一个文件no_parts_list。
- native_bom_database_read=false。

要求：
- 保留这些状态，不把not_detected转成已确认空白、0或“无”。
- 保留全部物理列，不把列语义未解决等同于列不存在。
- 区分行数完整、物理列完整、值完整、语义完整及原生数据库是否读取。
- partial导出需有明确的接受机制，不能默默替代用户要求的完整结果。
- 已接受部分结果时，名称、工作表说明和工具返回均标注partial。
- 工作簿中人类可读的“未检测”标记应与机器可读状态对应，不能混淆成真实来源值。

六、让 evidence 能真正补齐证据

基于现有evidence模式增强，而不是重新返回整幅代理图形。

至少支持：
- 按result_id、table_id、column_id定位组合表头。
- 返回表头原文、坐标、父子关系和必要的局部网格证据。
- 按row_id/column_id返回目标单元格的读取证据。
- 明确区分没有检测到文字、已证明空白、解码失败和位置歧义。

证据结果必须紧凑、可分页、可解析。
如果现有证据不能解除歧义，明确返回unresolved及原因，不凭“常见表格习惯”命名。
不要为获取保存显示证据自动启动或切换CAD。

七、只选择一条导出与交付路径

明确区分：
A. workstation：写入用户工作站授权目录。
B. artifact/download：向客户端提供其协议真实支持的可下载工件。

工作站路径：
- 返回明确的delivery_type和实际位置。
- 不声称已生成浏览器可下载附件。
- 不覆盖现有文件。
- 支持显式的新文件名，或返回冲突后可用的非破坏性选择。
- 自动改名如要支持，必须显式选择策略并在结果中报告最终路径。
- export_target_exists应为结构化冲突，不返回“检查图纸是否损坏”等不相关hint。

可下载工件：
- 先确认MCP客户端实际支持的资源读取、附件或文件传输机制。
- 不能伪造resource://链接，不能把Windows路径当Linux沙箱路径。
- 如果协议支持，通过受控资源引用交付，包含名称、大小、MIME、校验值和有效期。
- 如果不支持，明确报告交付能力缺口，并给出最小集成方案；不要同时触发另一套模型写脚本流程。
- 不将整个xlsx转换为巨大base64文本注入模型上下文。

八、可靠性与安全

- result_id、导出任务、数据资源均继承用户/会话权限与有效期。
- 校验路径穿越、输出目录授权、符号链接、现有文件覆盖。
- 使用临时文件加最终发布，防止失败留下貌似成功的半文件。
- 处理同一导出请求的重复调用，返回已有任务/结果或明确状态，避免重复副作用。
- 耗时导出若采用异步任务，提供真实状态查询；不让Agent盲目重复提交。
- 文件交付失败与Excel生成失败分别表达。
- 防Excel公式注入：来源文本不能自动变成公式。
- 保留前导零、中文、精度、单位及原始类型。
- 允许受信模板公式时，与来源文本严格区分。
- 仅读取显示表不能宣称原生ACMBOM已验证。
- 不为提速放弃导出后校验。

九、导出校验

保存后重新打开，并自动核对：
- 全部行列、表头和来源映射；
- 每个导出值与快照数据一致；
- 未检测、空白、歧义状态完整保留；
- 图号文本、数量类型、中文和特殊字符；
- 无意外公式、错误单元格或缺页；
- 文件大小与校验值。

返回结构化validation摘要，而不是仅有“成功”一句话。

这只能证明导出与当前快照一致，不能替代源CAD或原生数据库独立核验。

十、分页与状态语义检查

当前某些末页has_more=false时仍出现truncated=true、complete_for_requested_scope=false。
请检查字段是否混用了：
- 因分页未返回全部；
- 因数据缺失/语义歧义而不完整；
- 因体积限制截断。

分别定义page_complete、data_complete等必要状态，保留兼容字段并文档化。
完整JSON分页不能让客户端误以为发生了字符串截断，也不能让partial被误认为只有下一页尚未读取。

十一、测试与性能验收

使用mock和临时文件，至少测试：
1. 三文件、两表各6行、8列，直接result_id导出，不需模型遍历数据页。
2. 多级表头、未知语义及40个未检测单元格，全部状态不丢失。
3. 完整数据与部分数据的不同返回、接受机制和文件标识。
4. 文件变化、快照过期、未授权result_id、跨会话读取。
5. 路径冲突不覆盖，错误kind/hint准确；重复请求不重复生成。
6. 中文、前导零、大整数、公式样式文本与类型正确。
7. 导出后逐单元格与快照比较。
8. 工件交付通过实际支持的客户端路径验证；不支持则测试清晰失败。
9. schema/data/evidence分页不漏项，通用summary不再塞入整份blocks/references。
10. 旧参数和旧导出调用保持兼容。

记录：
- 解析/快照读取次数；
- schema/data/evidence输出字节与字符；
- Excel生成、重开校验、发布/交付时间；
- 重复请求次数及是否复用结果。

交付：
- 当前代码缺口与最小改动说明。
- 精确调用示例：schema→必要evidence→export→交付/查询。
- 完整导出、部分导出、文件冲突、过期及交付不支持的示例。
- 测试命令、结果、性能数据和仍不支持的情况。

最终验收：
Agent不再手抄全部BOM，也不再临时生成Excel脚本；
导出直接消费同一读取快照；
文件生成和交付使用单一路径；
数据完整性、来源和验证边界明确；
不通过减少安全校验或隐藏缺失数据来提速。

不要承诺固定节省多少秒。先验证服务端数据正确性和导出协议，再用客户端新会话检查模型轮次、脚本生成是否消失及端到端耗时。
```

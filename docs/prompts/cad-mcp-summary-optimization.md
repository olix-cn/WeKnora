# CAD Assistant MCP 紧凑摘要优化提示词

以下代码块可整体复制给 CAD Assistant MCP 服务端的开发 AI。

```text
请继续优化 CAD Assistant MCP 的 drawing_rename_files 返回协议。本轮重点是让默认 summary 真正紧凑、完整、可判断，而不是继续优化磁盘重命名速度。

一、已验证的问题

最近一次真实会话：
- 总耗时 56.43 秒，8 次模型调用累计 50.28 秒。
- Agent 已将字段映射和执行方案合并为一次确认。
- 应用时保持原参数，未补填 field_map。
- 首次预览、预览回读、应用使用相同 preview_id 和 plan_sha256。
- 实际 CAD 工具累计约 2.41 秒，不是主要瓶颈。

但返回体积问题仍存在：
1. 首次预览显式使用 detail="summary"、diagnostics=false，仍返回约 25.5 KB 文本。
2. 三个文件分别包含 45、47、31 条告警，全部 blocks_attribute_read=false。
3. 非阻塞告警紧凑 JSON 合计约 23.35 KB，占结果约 91%。
4. WeKnora 在模型可见工具结果超过 24000 字符后截取头尾，截断发生在 JSON 字符串内部，模型看到的不再是完整合法 JSON。
5. Agent 随后使用相同 preview_id 再次读取 summary，但仍得到约 25.5 KB 的结果，再次截断。
6. 这次额外回读的工具执行仅约 115 毫秒，但前置模型调用约 6.76 秒。

因此，本轮目标是：
- 一次默认预览就给出完整、紧凑的决策证据。
- 非阻塞诊断详情不挤占预览计划。
- 回读已有预览不重新解析文件，并确实返回紧凑摘要。
- 不降低权限、确认、冲突检查或预览有效性校验。

二、工作边界

1. 先阅读仓库说明、AGENTS.md，检查 Git 状态，不覆盖已有改动。
2. 先定位：
   - drawing_rename_files 注册和 input_schema；
   - summary/full 结果构造；
   - 文件解析告警收集；
   - 已有 preview_id 回读；
   - 应用结果构造；
   - MCP text 与 structuredContent 序列化。
3. 先说明当前返回过大的实际来源，再实现最小修复。
4. 不修改 WeKnora 服务端、模型配置或客户端截断上限。
5. 不安装依赖、不重启生产服务，不对真实用户文件执行写入测试。
6. 不隐藏阻塞问题，不让模型依靠截断内容决定执行。

三、默认 summary 的设计要求

A. 保留完整业务证据

默认 detail="summary" 应包含：
- ok、status、dry_run；
- preview_id、plan_sha256、expires_at；
- can_apply、blocked、confirmation_required；
- 文件总数、可执行数、阻塞数；
- validation，包括是否必须复查及原因；
- 每个文件的 source、target、status；
- resolved_field_map、mapping_basis、必要 values；
- 必要的读取完整性信息；
- 全部阻塞问题和影响本任务的风险；
- 非阻塞告警摘要及详情获取方式；
- 操作范围，例如仅修改文件名，不改图纸内容、外部参照或附属文件。

不要只返回一句“预览成功”，也不要只提供统计而缺少完整改名前后计划。

B. 聚合非阻塞告警

对经现有校验明确判定不影响本次属性读取和文件重命名的告警：
- 默认不逐条返回长 message、原始解析器对象和重复上下文。
- 按稳定 code 或 category/scope 聚合，返回数量与影响说明。
- 保留每文件计数，必要时增加批次级去重汇总。
- 不把“类别相同”自动等同于“风险相同”；不同影响等级分别聚合。
- 缺少影响分类或无法证明非阻塞的告警，不得默认归入 harmless。
- 影响本任务的风险与阻塞项必须明确显示，不能因追求体积目标而删除。

可采用类似结构，但先评估兼容性：

"warning_summary": {
  "total": 45,
  "blocking": 0,
  "groups": [
    {
      "code": "unsupported_custom_non_graphical",
      "count": 35,
      "blocks_attribute_read": false,
      "effect": "..."
    }
  ],
  "details_available": true
}

effect 必须依据现有校验结论生成，不允许为了摘要而编造“不影响操作”。

C. 不使用字符串硬截断

- 不对最终 JSON 直接截取字符或字节。
- 不在 JSON 中插入省略号来代替未返回的业务计划。
- 完整结果无法安全放入单次响应时，应采用结构化分页或明确阻止执行并说明如何取全。
- 不可以只返回前几个文件，却仍宣称整个批次完整、可执行。

对于此次 3 文件、123 条非阻塞告警的合成回归样本：
- 默认 summary 目标为 5 KiB 左右或更小；
- 至少应低于 8 KiB；
- 这是验收目标，不允许通过丢失必要证据或截断达成。

四、full / 诊断详情

1. detail="full" 或明确的详情接口才返回原始告警及解析证据。
2. 已有 preview_id 的详情读取应读取保存的证据，不重新打开或解析文件。
3. 告警很多时支持分页，返回：
   - offset / limit；
   - total；
   - has_more / next_offset；
   - 对应文件或稳定 file_id。
4. 不使用绝对宿主路径、凭证或内部敏感信息作为“详情入口”。
5. 详情读取必须继承原有会话、用户和预览访问权限。
6. summary 到 full、分页或 diagnostics 的切换属于展示行为，不应改变业务计划、preview_id、plan_sha256，也不能延长预览有效期。
7. 若当前工具不适合加入这些参数，提出兼容方案；不要随意增加多个职责重复的工具。

五、已有预览回读

以下调用应返回同一份冻结计划的紧凑摘要：

drawing_rename_files(
  paths=原paths,
  filename_format=原格式,
  dry_run=true,
  preview_id=原preview_id,
  detail="summary",
  diagnostics=false
)

要求：
- 不重新解析图纸。
- 不重新解析或替换字段映射。
- 不创建新的计划或 preview_id。
- 不改变 plan_sha256。
- 不刷新 expires_at。
- 不因省略 field_map 自动回填 explicit 映射而改变计划身份。
- 参数与原计划不一致时明确拒绝，不能悄悄返回另一个计划。
- 正式应用仍按现有协议校验源文件变化、目标冲突、权限和过期状态。

六、应用结果也应紧凑

正式应用成功后，默认 summary 返回：
- committed / 部分失败等明确状态；
- 原 preview_id、plan_sha256；
- 成功、失败、未执行数量；
- 每个文件 source、target、最终状态；
- 必须处理的问题、验证范围；
- 是否执行了回滚及回滚结果（如适用）。

不要再次复制整批原始解析告警。
可以引用同一预览的告警摘要和按需详情，但不能省略新发生的风险或失败原因。

不要仅凭 MCP 传输成功返回业务成功，也不要将“文件已重命名”描述为“CAD 已独立验证”或“图纸内容已保存”。

七、MCP 序列化与兼容性

当前客户端记录中，content text 与 structuredContent 包含相同业务数据，WeKnora 还会保存模型可见 output。

请检查：
- 是否存在服务端重复序列化或多份完整结果拼接。
- text 与 structuredContent 的字段和值是否一致。
- 若需要同时提供两种形式，两者都应使用紧凑 summary，而不是一份摘要、一份完整告警。
- full 只在显式请求时返回。

不能仅为去重就删除客户端依赖的 text 或 structuredContent；用兼容测试确定。
不要声称“模型收到三份内容”，这需要客户端注入路径证据，本轮没有验证。

八、工具描述与契约

更新真实暴露给 MCP 客户端的 description / input_schema：
- 明确 summary 已包含整个批次的必要执行证据。
- 明确 full 是诊断详情，不是执行前的固定步骤。
- 明确已有有效且完整的预览，不需要例行逐文件再预览。
- 明确展示参数不会改变计划身份，哪些业务参数变化会导致拒绝或要求新预览。
- 保留“dry-run → 用户确认 → 应用同一计划”的要求。
- 工具结果仅返回数据，不夹带覆盖客户端权限或安全规则的指令。

九、测试要求

使用 mock、临时目录和合成图纸元数据，至少覆盖：

1. 三文件分别含 45、47、31 条非阻塞告警：
   - 默认 summary 不含全部原始 message；
   - JSON 完整可解析；
   - 总数、分类计数、逐文件计划正确；
   - 返回体积满足目标。

2. 混合阻塞 / 非阻塞告警：
   - 阻塞原因完整可见；
   - can_apply=false；
   - 不将未分类告警默认视为无害。

3. 字段缺失、空值、多候选、显式映射和唯一别名：
   - 不因摘要优化改变原有判断。

4. 预览回读：
   - 属性解析器调用次数仍为一次；
   - preview_id、plan_sha256、expires_at 不变；
   - 参数不一致被拒绝。

5. 详情读取及分页：
   - 能取回全部原始告警；
   - 不漏项、不重复；
   - 权限与过期处理符合原协议；
   - 不产生写入副作用。

6. 应用：
   - 必须引用有效计划；
   - 文件变化、目标冲突、过期、重复应用及部分失败处理不退化；
   - 不重新返回全部历史告警。

7. MCP text / structuredContent：
   - 业务含义一致；
   - 兼容现有客户端。

8. 大批次：
   - 不静默截断计划；
   - 分页或受限返回有明确完整性状态。

十、交付与验收

提交：
- 修改文件和关键设计。
- 优化前后 summary / full / apply 的字节数与字符数。
- 三文件回归样本的示例响应。
- 测试结果和兼容性说明。
- 尚未解决的限制。

验收标准：
默认一次预览就能得到完整、紧凑、可确认的重命名计划；
不再被非阻塞告警撑到客户端截断；
已有预览回读不重新解析文件；
不以减少检查、隐藏风险或绕过确认来提速。

不要承诺固定节省多少秒。服务端能够验证返回体积和调用行为；端到端模型轮次与耗时需上线后用新会话复测。
```

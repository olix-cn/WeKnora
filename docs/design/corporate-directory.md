# 组织管理与部门

## 产品入口

- 位于“设置 → 系统管理 → 组织管理”，与系统设置同级，不增加主界面业务菜单。
- 原系统设置移除用户页签；旧 `?section=system-global&panel=users` 及管理员人员入口兼容到组织管理。
- 权限仍为当前有效系统管理员；空间owner/admin、跨空间运维身份或API key不自动获得人员管理权限。接口始终重查真实账号状态与系统管理员标志，不受空间RBAC日志模式放宽。

## 数据与行为

第一版为单公司、树形部门、每人一个主部门，名称／编码／排序／负责人可维护。部门与 `tenants`、原跨空间共享的 `organizations` 完全独立。

- PG142／SQLite58新增 `corporate_directories`、`corporate_departments`、`corporate_personnel`。账号没有profile即“未分配部门”，不改写旧账号或角色。
- 不给部门附加知识库授权；调部门不改变空间成员ID、默认空间、空间角色、系统管理员或已有知识库名单。
- 部门禁止循环和超过32层的结构，同级名称及非空编码不重复；有成员／子部门／负责人不可删除。层级最多2000部门，超限明确拒绝，不截断后放行。
- 负责人仅为组织信息，必须为有效直接成员；调动前先解除负责人。账号停用或软删除由数据库触发器清除负责人并递增部门版本，不恢复账号时自动复活负责人。
- 成员批量调动最多100人，逐人expected_version校验，全批事务；一个冲突或审计失败整批回滚。缺profile版本为0；创建后从1递增。
- 搜索在后端匹配账号、邮箱和姓名，先筛部门／子部门／状态再count及分页，通配符当文字处理。只返回人员管理投影，不返回密码hash／偏好／配置。
- 新建账号选择姓名和部门时，身份、默认空间成员、人员profile及目录审计同事务提交。重试已存在账号不覆盖姓名、部门、密码或权限，身份／归属不匹配返回冲突。
- 部门、人员变更与系统范围审计同事务。审计仅记录目标标识、版本、父部门／人数等，不记录密码或用户文档。

## 隐藏共享空间

产品策略固定隐藏原共享空间（`organizations`）界面能力，能力请求失败也不显示；主菜单、命令搜索及旧路由复用该策略。知识库／智能体编辑器移除分享页签及挂载内容。保留已有分享表、资源读取和权限判断；不删除数据、不撤销分享、不宣称关闭底层管理API。
